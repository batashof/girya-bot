# CLAUDE.md

Личный Telegram-бот для домашних тренировок: программа дня, темы и комплексы под проблему.
Цель — здоровье, а не масса. Упор — спина, лопатки, шея. Инвентарь: пара гирь по 5 кг + вес тела.
Стек: TypeScript + grammY + Cloudflare Workers + D1. Требование: $0/мес.

## Прежде чем писать код

Документация в `docs/` — источник истины, а не заметки. Порядок чтения по задаче:

- меняешь программу тренировок → `docs/05-training-program.md`, `docs/06-exercise-library.md`
- трогаешь схему БД → `docs/03-data-model.md`
- добавляешь команду/экран → `docs/04-bot-ux.md`
- деплой, секреты, лимиты → `docs/08-deployment.md`
- «почему так, а не иначе» → `docs/09-adr.md`

Если реализация расходится с документом — правится либо код, либо документ, но не остаётся расхождения.

## Правила кода

- `src/domain/` — чистый TypeScript. Не импортирует Telegram, D1, Workers-API. Только сюда пишутся тесты, и они обязательны для движка программы и прогрессии.
- `src/bot/` — команды и клавиатуры. Все тексты в `src/bot/ui/`, на русском, без i18n (ADR-009).
- `src/data/` — тонкие функции над D1, без ORM.
- `src/platform/` — единственное место, где живёт специфика Workers.
- TypeScript strict, без `any`. Ошибки не глотаем: любое исключение уходит владельцу в Telegram.
- Каждый подход пишется в базу сразу — тренировка не должна теряться при падении.

## Инвентарь и контент

- Веса гирь и рост/вес/возраст берутся из БД пользователя, в коде не хардкодятся. Стартовая конфигурация (2×5 кг, 190/73/30) — это сид, а не константы.
- Прогрессия — по лестнице рычага, не по весу (ADR-011): повторы → темп → следующий вариант → внешний вес. Состояние хранится по цепочке движения (`push`, `row`, `squat`, `hinge`, `core`), не по коду упражнения.
- Новое упражнение = строка в `docs/06-exercise-library.md` + запись в `data/exercises.seed.json` + пересборка сида. Обязательные поля: `swap_group`, `neck_safe`, а для силовых — `chain` и `chain_level`. Если упражнение попадает в шаблон дня или в лестницу — ещё и схема движения в `scripts/build_demos.py`.
- `cues` пишутся как порядок действий, а не как напоминание тому, кто и так умеет: карточка режет их по предложениям в нумерованный список. Одно предложение — один шаг, 3–5 штук.
- Упражнения с `neck_safe = 0` исключаются в дни с болью ≥2 — это не опция, а инвариант.
- Тренировки по теме (`kind = 'theme'`) и комплексы (`kind = 'complex'`) никогда не влияют на прогрессию и streak (ADR-016, ADR-018). Микро-блоков (`/mini`) больше нет (ADR-017); `kind = 'mini'` — только в истории.
- Доза — повторы и секунды на повтор (ADR-017). У упражнения обязательны `dose_sets`, `dose_reps`, `dose_rest_sec`, `rep_sec`; в `cues` не бывает чисел времени и повторов — сборка сида это проверяет.
- Тема — группа упражнений (`exercises.group_code`), строка `templates` с `kind = 'theme'`. Новая тема = запись в `themes` в `data/templates.seed.json` + пересборка сида.
- Комплекс — готовый набор под одну проблему: строка `templates` с `kind = 'complex'` и пунктами. Новый комплекс = запись в `complexes` в `data/templates.seed.json` (код с `C`, без `follow_chain`) + пересборка сида + описание в `docs/07`.

## Команды

```bash
pnpm dev        # локальный воркер + dev-бот в polling
pnpm test       # Vitest по domain/
pnpm typecheck
pnpm demos:build # перерисовать схемы движения (нужен Pillow)
pnpm deploy     # wrangler deploy руками: CI деплоит из main, только если в секретах есть CLOUDFLARE_API_TOKEN
```

## Чего не делать

- Не добавлять платные зависимости и сервисы (главное требование проекта).
- Не звать LLM в рантайме бота (ADR-003).
- Не коммитить `.dev.vars`, токены, дампы базы.
- Не добавлять мультипользовательский режим, регистрацию, веб-морду.
- Не выкидывать шейный протокол из шаблонов дней ради экономии времени (ADR-008).
- Не планировать время тренировки: ни бюджета минут, ни «~N мин», ни обрезки дня по времени (ADR-018). Время в боте — только секунды на повтор и факт в статистике.
- Не проектировать под «когда купим гири потяжелее»: программа рассчитана на 5 кг всерьёз и надолго.
