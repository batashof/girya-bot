# 02. Архитектура

## Общая схема

```
   Telegram
      │  webhook (HTTPS, X-Telegram-Bot-Api-Secret-Token)
      ▼
┌──────────────────────────────────────────────┐
│  Cloudflare Worker  (girya-bot)              │
│                                              │
│  fetch()      → grammY webhookCallback       │
│  scheduled()  → планировщик напоминаний      │
│                                              │
│  src/                                        │
│   ├── bot/         команды, сцены, клавиатуры│
│   ├── domain/      движок программы (чистый) │
│   ├── data/        доступ к D1               │
│   └── platform/    Workers-специфика         │
└───────────────┬──────────────────────────────┘
                │  SQL
                ▼
        ┌───────────────┐
        │ Cloudflare D1 │   (SQLite)
        └───────────────┘
```

Никаких очередей, кэшей, воркеров-компаньонов. Один воркер, одна база.

## Почему такой стек

Полное обоснование — [09-adr.md](09-adr.md). Коротко:

- **Cloudflare Workers** — бесплатный тариф без «засыпания» сервиса. Render Free усыпляет сервис после 15 минут простоя, и первое сообщение утром ждало бы холодного старта.
- **Cron Triggers** доступны на бесплатном тарифе — это и есть механизм утренних напоминаний. Отдельный планировщик не нужен.
- **D1** — SQLite, знакомый SQL, бесплатных лимитов хватает на одного пользователя с запасом в тысячи раз.
- **grammY** — актуальный TS-фреймворк для ботов с официальной поддержкой Workers-рантайма.
- **TypeScript** — то, на чём я и так пишу каждый день.

**Правило слоёв:** `domain/` не импортирует ничего из `bot/`, `data/`, `platform/` и не знает про Telegram. Только так его можно тестировать и перенести на другой хостинг за день.

## Два входа в воркер

### 1. `fetch()` — webhook Telegram

Проверка `X-Telegram-Bot-Api-Secret-Token` до любой обработки. Чужой запрос — `401`, без обращения к базе.
Ответ Telegram отдаём быстро; долгие действия — через `ctx.api` после ответа (в Workers доступен `waitUntil`).

### 2. `scheduled()` — cron

```toml
[triggers]
crons = ["*/5 * * * *"]
```

Каждые 5 минут воркер смотрит: кому по его локальному времени пора напомнить и кому ещё не отправляли сегодня. Точность ±5 минут — для утреннего напоминания более чем достаточно, а расход укладывается в бесплатные лимиты с запасом (≈8 640 вызовов в месяц против лимита 100 000 в день).

Часовой пояс хранится у пользователя как IANA-строка (`Europe/Warsaw`), локальное время считаем через `Intl.DateTimeFormat` — в Workers есть полный ICU.

## Конфигурация и секреты

| Имя | Тип | Что это |
| --- | --- | --- |
| `BOT_TOKEN` | secret | Токен от @BotFather |
| `WEBHOOK_SECRET` | secret | Случайная строка для `secret_token` вебхука |
| `OWNER_TELEGRAM_ID` | var | Мой Telegram user id — единственный, кого бот обслуживает |
| `DB` | D1 binding | База |

Секреты — только через `wrangler secret put`. В репозитории их нет и не будет; `.dev.vars` в `.gitignore`.

## Безопасность

- Вебхук закрыт секретным токеном; путь вебхука дополнительно содержит случайный сегмент.
- Guard владельца в первом middleware: любой `from.id !== OWNER_TELEGRAM_ID` получает короткий отказ, дальше цепочка не идёт.
- Персональных данных минимум: id, часовой пояс, веса гирь, логи тренировок и оценка боли 0–3. Ни имени, ни почты, ни геолокации.
- Репозиторий приватный.

## Стоимость

| Ресурс | Бесплатный лимит | Наш расход |
| --- | --- | --- |
| Workers requests | 100 000/день | ≈300/день (≈290 cron + сообщения) |
| Workers CPU | 10 мс/запрос | единицы мс |
| D1 storage | 5 ГБ | < 5 МБ за годы |
| D1 rows read | 5 млн/день | тысячи |
| D1 rows written | 100 тыс./день | сотни |
| GitHub Actions | 2 000 мин/мес (приватные) | ~1 мин на деплой |

Итого: **$0/мес**, с запасом на два порядка. Ни один компонент не требует привязки карты.

## Наблюдаемость

- `wrangler tail` — живые логи при отладке.
- Ошибки в обработке апдейта → сообщение владельцу в Telegram (`Упал на /today: …`). Для личного бота это лучший алертинг, который вообще возможен, и он бесплатный.
- Таблица `events` — минимальный аудит: что и когда бот отправил.

## Локальная разработка

- `pnpm dev` — бот в long-polling против локального `wrangler dev` с локальной D1 (`--local`), без вебхука и без прода.
- Отдельный тестовый бот от @BotFather, чтобы не ломать боевой.
- `pnpm test` — Vitest по `domain/`, без сети и без базы.
