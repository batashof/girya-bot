# 01. План работ

Оценки — в часах чистой работы. Порядок этапов жёсткий: каждый следующий опирается на предыдущий.
Каждый этап заканчивается рабочим деплоем в проде (бот всегда живой, просто умеет меньше).

## M1 — Скелет и деплой (≈3 ч)

Цель: бот отвечает `/ping` в проде, деплой автоматический.

- [x] `pnpm init`, TypeScript strict, ESLint + Prettier, Vitest
- [x] grammY + адаптер Cloudflare Workers, webhook с `secret_token`
- [x] Guard по `OWNER_TELEGRAM_ID` — остальным «этот бот личный»
- [x] `wrangler.toml`: биндинг D1, cron triggers, секреты
- [x] Команды `/ping`, `/help`
- [x] GitHub Actions: `deploy.yml` на push в `main`
- [x] Скрипт `pnpm dev` — локальный запуск в polling-режиме (без вебхука)

**Готово, когда:** пишу `/ping` в Telegram — приходит `pong` из прода.

Код написан и проверен локально (typecheck, тесты, сборка воркера, маршрутизация вебхука:
404 на чужой путь, 401 на неверный `secret_token`). Осталось разовое, что делается руками
по [08-deployment.md](08-deployment.md): бот у @BotFather, `wrangler d1 create girya`,
подстановка `database_id` / `OWNER_TELEGRAM_ID` / `WEBHOOK_PATH` в `wrangler.toml`, секреты
и `setWebhook`.

## M2 — Данные и контент (≈4 ч)

Цель: библиотека упражнений и шаблоны тренировок лежат в D1.

- [x] Миграции D1 (`migrations/0001_init.sql`), схема из [03-data-model.md](03-data-model.md)
- [x] Сид: 61 упражнение из [06-exercise-library.md](06-exercise-library.md) в `data/exercises.seed.json` — с `chain` и `chain_level`
- [x] Сид: 7 шаблонов дня (W-A…W-G) + лестницы прогрессии из [05-training-program.md](05-training-program.md)
- [x] Слой доступа к данным (тонкие функции, без ORM)
- [x] Онбординг: часовой пояс, время, бюджет минут, рост/вес/возраст, инвентарь, стартовые уровни
- [x] `/today` — показать тренировку дня текстом

**Готово, когда:** `/today` показывает корректный день недели с моими весами.

Сид собирается из JSON в миграцию скриптом `pnpm seed:build` — источник истины остаётся
рядом с документацией, а в базу уезжает обычная миграция. Резолвер дня (шаблон + лестницы +
бюджет минут) написан здесь же, потому что без него `/today` нечего показывать; в M3
остаются пошаговый режим, запись подходов и шаг по лестнице.

## M3 — Движок тренировки (≈6 ч)

Цель: пошаговое прохождение и логирование.

- [x] Резолвер дня: дата + микроцикл + неделя блока + бюджет минут → конкретный набор подходов (сделан в M2)
- [x] Пошаговый режим: карточка упражнения, кнопки `Готово / Тяжело / Легко / Больно / Пропустить`
- [x] Замена упражнения (`/swap`) — альтернатива из той же группы
- [x] Запись `sessions` и `session_sets`
- [x] Логика прогрессии по лестницам: повторы → темп → следующий вариант → внешний вес; откат при «тяжело»
- [x] Разгрузочная неделя (4-я в блоке): все дни по 10 минут (сделана в M2)
- [x] Юнит-тесты движка (генерация дня, шаг по лестнице, откат, деload) — это единственная часть, где тесты обязательны

**Готово, когда:** прохожу тренировку целиком, назавтра цели пересчитаны по лестнице.

Шаг пошагового режима — это упражнение: у каждого своё сообщение со схемой движения,
заданием и техникой, шейный протокол разворачивается по одному (ADR-015). Позиция
хранится в `ui_state`, поэтому `/go` после закрытого чата или падения продолжает с того
места, где остановился, а не начинает утро заново.

«Больно» и «Пропустить» снимают упражнение целиком, а не подход: добивать через боль —
ровно то, чего программа не делает ([10-safety.md](10-safety.md)). На прогрессию ни то,
ни другое не влияет — это дело адаптации дня (M4).

## M4 — Напоминания и адаптация (≈4 ч)

Цель: бот сам стучится и подстраивается под состояние.

- [x] Cron trigger каждые 5 минут → очередь напоминаний с учётом часового пояса
- [x] Утреннее напоминание с кнопками `Начать / Перенести на час / Пропустить`
- [x] Вечерний «добивочный» пинг, если тренировка не начата
- [x] Ежедневный вопрос про шею (0–3) — до тренировки
- [x] `/pain` и оценка 2–3 → завтра автоматически разгрузочный/шейный день
- [x] `/mini` — микро-блоки на 3 минуты + опциональные напоминания днём
- [x] `/settings`: время, бюджет минут, профиль, инвентарь, ручная правка уровней
- [x] Streak: «заморозка» на 1 пропуск в неделю

**Готово, когда:** неделю не трогаю бота руками, а тренировки идут.

Напоминание не догоняет: если cron не сработал или воркер был недоступен, окно в 90 минут
закрывается и бот молчит. «Доброе утро» в четыре часа дня хуже, чем пропущенное напоминание.

Серия прощает один пропуск в неделю, не тратит заморозку на субботу (день по желанию)
и не рвётся на паузе. Иначе первый же занятый вторник обнулял бы месяц, и смысл метрики
пропадал бы ровно тогда, когда она нужнее всего.

## M5 — Аналитика (≈3 ч)

- [x] `/stats` — частота, минуты, уровни по лестницам, тренд боли в шее
- [x] `/streak`
- [x] Недельный отчёт по воскресеньям вечером
- [x] `/export` — CSV всех сессий в файл

**Готово, когда:** вижу график «боль в шее по неделям» и понимаю, помогает ли.

Истории прогрессии отдельной таблицей нет: `progression` держит только текущее состояние
(ADR-007). Поэтому «что изменилось за неделю» пишется в журнал `events` в момент смены
ступени, и недельный отчёт читает его оттуда.

Плоский тренд по шее при шести неделях регулярных тренировок `/stats` называет вслух:
это сигнал идти к физиотерапевту, а не делать ещё один подход Y-T-W
([07-neck-and-back.md](07-neck-and-back.md)).

## M6 — Приятное сверху (по желанию, ≈4 ч)

- [x] `/howto <код>` — техника и типичные ошибки
- [x] Ссылки на демо-видео у каждого упражнения
- [ ] Таймер отдыха через отложенные сообщения (минутный cron)
- [ ] Режим «в поездке» — программа без гирь (только вес тела и резина)
- [ ] Экспорт в Apple Health через Shortcuts (webhook)

`/howto` находит упражнение по коду или по началу названия — коды помнить необязательно.
Кнопка «Как делать» есть в карточке каждого подхода; в карточке шейного протокола техника
расписана прямо на месте, потому что это семь упражнений подряд и семь кнопок там были бы
хуже семи строк.

Демонстрации двух видов. Встроенные — рисованные схемы движения (`pnpm demos:build`):
девять упражнений, где техника решает, от свинга до chin tuck. Свои — командой `/gif <код>`:
файл остаётся у Telegram, бот хранит только `file_id` и предпочитает его встроенной схеме
(ADR-014). Если нет ни того, ни другого, кнопка ведёт на поиск по названию.

## Порядок и зависимости

```
M0 ──► M1 ──► M2 ──► M3 ──► M4 ──► M5 ──► M6
              │              │
              └── контент ───┘  (упражнения можно дополнять в любой момент)
```

Суммарно до полноценного бота (M1–M5): **≈20 часов**.

## Риски

| Риск | Влияние | Что делаем |
| --- | --- | --- |
| Cloudflare меняет бесплатные лимиты | Придётся переезжать | Вся логика — чистый TS, привязка к платформе только в `src/platform/*`. Переезд на Render/VPS — день работы |
| Программа окажется скучной и заброшу | Проект мёртв | Микроцикл разнообразен по формату (силовой / комплексы / восстановление), streak и недельный отчёт как обратная связь |
| Шея не пройдёт от упражнений | Основная цель не достигнута | Логируем оценку боли; если за 8 недель тренда нет — это сигнал идти к врачу/физиотерапевту, см. [10-safety.md](10-safety.md) |
| Скука от ручного логирования | Пропуск логов → сломанная прогрессия | Максимум одна кнопка на подход, значения по умолчанию всегда предзаполнены |
